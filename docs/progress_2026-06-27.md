# FFXIV Prism Progress — 2026-06-27

## Current state

- Dataset: 50 labeled glamour pages and 201 screenshots.
- Evaluated core slots: `HEAD`, `BODY`, `HANDS`, `LEGS`, and `FEET`.
- Effective end-to-end evaluation cases: 943 slot labels.
- GPU environment: PyTorch 2.11.0 + CUDA 13.0 on an RTX 5070 Ti.
- Hugging Face, Torch, and pip caches are rooted under `var/cache/` on the D
  drive through persistent variables in the `ffxiv-prism` Conda environment.

## Retrieval improvement

`scripts/evaluate_glamour_fusion.py` now performs score-level fusion before
piece-level candidate deduplication. It z-score normalizes each model's
per-crop candidate scores, combines them, and evaluates the existing crop
weighting profiles.

Best Top-1 configuration:

- DINOv2-base color weight: 0.75
- CLIP ViT-B/32 color weight: 0.25
- Crop profile: `context`
- Tag penalties: `none`
- Crop aggregation: `max`

| Method | Appearance Top-1 | Recall@10 | MRR |
|---|---:|---:|---:|
| DINOv2-base color | 5.09% | 11.35% | 0.067 |
| DINOv2-base + CLIP score fusion | **5.73%** | **13.47%** | **0.078** |

The 0.60/0.40 fusion variant is preferable when candidate coverage matters
more than Top-1: it reaches 14.53% Recall@10 with 5.41% Top-1.

Best-fusion per-slot metrics:

| Slot | Top-1 | Recall@10 |
|---|---:|---:|
| HEAD | 2.59% | 7.77% |
| BODY | 12.56% | 29.65% |
| HANDS | 3.06% | 5.10% |
| LEGS | 4.30% | 12.90% |
| FEET | 5.92% | 11.24% |

These weights were swept on the current labeled evaluation set. Treat the gain
as a useful engineering result, not yet an unbiased generalization estimate.
The next training/evaluation iteration should split by `glamour_id`.

## Next accuracy work

### Held-out domain-adaptation result

The project now has a deterministic 30/10/10 `glamour_id` train/validation/test
split. A rank-16 slot-conditioned residual adapter is trained with screenshot
crops as queries and all matching clean renders as multi-positive targets.
Training stops from validation crop recall; the held-out test set is not used
for checkpoint or profile selection.

| Held-out test method | Top-1 | Recall@10 | MRR |
|---|---:|---:|---:|
| DINOv2-base baseline | 6.63% | 16.87% | 0.095 |
| Adapted DINOv2-base | 6.63% | 22.89% | 0.115 |
| Adapted DINOv2 + CLIP fusion | 7.83% | 19.28% | 0.112 |
| Precision-head / recall-tail cascade | **7.83%** | **24.10%** | **0.132** |

The cascade takes rank 1 from the validation-selected DINOv2/CLIP fusion and
fills ranks 2–10 from the adapted DINOv2 results. Relative to the held-out
baseline, Recall@10 improves by about 42.9%.

Per-slot checkpoint selection was tested and rejected: it looked better on
individual validation crops but reduced held-out Recall@10 to 13.3%. The final
checkpoint therefore retains the globally selected epoch 2 state.

The split is group-isolated, but the fixed test results were inspected during
the later cascade engineering pass. Treat it as a development test rather than
a final unbiased benchmark; the next dataset expansion should reserve fresh
glamour groups for one-time confirmation.

### Human parsing and background-mask ablation

`mattmdjaga/segformer_b2_clothes` now supplies two query-only mask variants:

- `person`: remove the game background while retaining all parsed person and
  clothing pixels;
- `slot`: retain labels mapped to the requested equipment slot, with a person
  mask fallback when the semantic region is too small.

Mask edges are dilated and feathered so thin equipment boundaries are less
likely to disappear. Candidate renders are unchanged.

Without domain adaptation, both mask variants were worse overall, although they
improved isolated slot metrics. After training the same rank-16 adapter, the
person-mask branch became a useful precision model. The final ensemble takes
Top-1 from the adapted person-mask branch and fills the remaining ranks from the
raw-image cascade:

| Group-isolated development test | Top-1 | Recall@10 | MRR |
|---|---:|---:|---:|
| Original DINOv2-base baseline | 6.63% | 16.87% | 0.095 |
| Raw-image cascade | 7.83% | 24.10% | 0.132 |
| Person-mask precision + raw recall | **9.04%** | **25.90%** | **0.147** |

Strict slot parsing is not selected: 92.0% of HANDS crops and 80.2% of FEET
crops fell back to the person mask because the ATR label set has no glove class
and often misses game footwear. Its best cascade reached only 6.02% Top-1 and
20.48% Recall@10.

The embedding evaluator also now refuses to build or overwrite an index from
empty metadata. This guard was added after an invalid custom-index invocation
exposed the unsafe behavior; the affected DINOv2 index was rebuilt and its
original 5.09%/11.35% full-set baseline was reproduced exactly.

### Assessment of the external proposal

- Adopted: dual-encoder fusion and explicit screenshot-to-clean-render domain
  adaptation.
- Worth testing next: human parsing or foreground masking as an isolated
  ablation, especially for BODY and FEET.
- Already contradicted by local evidence: grayscale DINOv2 did not improve the
  overall result, and FashionCLIP color was weaker than the DINOv2/CLIP family.
- Faiss remains an inference-speed optimization; it does not address the
  representation/domain gap responsible for current misses.

### Next work

1. Expand the labeled glamour set and reserve fresh blind-test groups before
   further adapter or mask tuning.
2. Prioritize `HANDS` and `HEAD`, where candidate recall remains weakest.
3. Try a game-domain foreground model only if new labels justify it; the current
   generic person mask already captures most of the useful parsing gain.
4. Add hard negatives from visually similar same-slot pieces while preserving
   same-appearance variants as positives.
