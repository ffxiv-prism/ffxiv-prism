# FFXIV Prism 装备识别阶段性交接（2026-06-29）

## 1. 阶段结论

本阶段完成了真实玩家搭配图采集、按 `glamour_id` 隔离的数据划分、
人物姿态分槽、正面全身质量审核、候选图对齐、DINOv2 参数微调、
非线性重排和一次性盲测。

当前目标 **appearance Top-1 接近 80% 尚未实现**。必须区分两类结果：

- 冻结高质量验证集上的最好结果为 **32.7% Top-1**，但 foreground
  分支只有 171 个有效 case，覆盖不完整，不能作为盲测泛化结论。
- 最新一次严格视觉审核、从未参与调参的盲测为 **13.3% Top-1 /
  20.0% Top-10**。这是当前最可信的跨 glamour 泛化证据。

核心瓶颈不是模型维度太小，而是玩家截图与标准模特图的域差异、
HANDS/FEET 的有效像素过少、相似装备之间的细粒度混淆，以及每件装备
真实穿着视角覆盖不足。hard-negative 训练有效，但尚不足以弥合该差距。

## 3. 当前有效工作流

### 3.1 采集与标签

1. 从 Eorzea Collection 的已知 glamour 关联链接构建有界扩充队列。
2. 只接受所有非空核心槽位都能精确映射到本地装备库的 glamour。
3. 页面给出的装备名和本地 `piece_id` 是训练真值；视觉大模型只用于
   图像质量、姿态和可见性审核，不应凭外观猜 exact item 标签。
4. 使用 `scripts/build_glamour_examples_dataset.py` 生成图像级样本。

本轮扩充队列为 `data/interim/glamour_expansion_queue_v1..v6*`。

### 3.2 原图前景与区域

正确的背景处理顺序是：

1. 在原始玩家图上检测人物主体。
2. 将人物主体以外像素标记为背景。
3. 在原图坐标系生成 HEAD/BODY/HANDS/LEGS/FEET 区域。
4. 区域裁剪完成后，再把背景位置合成为固定灰色或透明。
5. 保留原图区域作为回退分支。

`src/ffxiv_prism/vision/human_parsing.py` 实现了人物前景和合成逻辑。
但当前 foreground 缓存并未覆盖全部 2,169 张图，且 v17 训练实际使用
`alternate_probability=0`。因此 foreground 结果只能视为有前景缓存样本
上的辅助实验，不能宣称已经形成全覆盖生产流程。

姿态区域由以下命令生成：

```powershell
python scripts\debug_outfit_regions.py `
  --dataset data\processed\glamour_examples.jsonl `
  --output-dir data\debug\outfit-regions-v6-1882 `
  --device cuda `
  --quiet `
  --skip-existing
```

目录名保留了早期的 `1882`，但其中 `summary.json` 当前实际覆盖 2,169 张图。

### 3.3 测试图质量门

只将主体较大、单人、正面或近正面、全身完整、无遮挡拼图的图片用于
“高质量正面全身”指标。

冻结白名单：

- `data/processed/front_fullbody_quality_final_v1.jsonl`
- `data/processed/front_fullbody_visual_reviews_v1.jsonl`
- 273 / 1,882 张通过，覆盖率 14.5%。

该白名单只覆盖第一次 1,882 张数据，用于保持历史验证可比性。新增
287 张不能因为未在白名单中就被当作质量失败；如要扩展白名单，必须
另建版本并完成全量视觉审核。

- `data/processed/blind_v5_front_fullbody_accepts.txt`

### 3.4 标准候选图

当前候选索引：

- `data/indexes/facebook-dinov2-base-slot-aligned-v2`
- 19,721 张源渲染。
- 27,057 个对齐候选。
- 768 维 DINOv2 embedding。

槽位策略：

- BODY：上半身裁剪。
- HANDS：`both_hands`、`left_arm_tight`、`right_arm_tight` 三个候选。
- HEAD/LEGS/FEET：全图。

`both_hands` 修复了标准手部图中双手抱胸、单侧裁剪会截断另一只手和
袖甲的问题。训练时强制纳入 `hands_arm_cover_context`，使玩家图与完整
双手候选具有对应视角。

### 3.5 模型

- `data/models/glamour_query_encoder_v17_534g_hardneg.pt`
- DINOv2-base 最后一层实际更新。
- 按 glamour 聚合多视图。
- 每槽位最多 3 个 crop。
- hard-negative weight 0.2，K=20，margin=0.5。

当前本地最佳已训练重排器：

- `data/models/glamour_pair_reranker_v9_534g_grouped.pt`
- 基于 v16 查询 embedding。
- 分槽输出头，按 glamour 聚合。

模型权重、候选索引、查询 embedding 和大体积逐案例报告均为本地生成

## 5. 已证伪或受限的方案

### 5.1 严格 slot mask

服装 human parser 经常把铠甲袖、手套、长靴误分为皮肤或上衣，导致
只保留残缺装备。视觉上明显比不带 mask 更差，不应恢复为默认流程。

### 5.2 标准候选图统一去模特

尝试了 human parsing、模板差分和分槽选择性去模特：

- 模板差分能保住袖甲，但同时保留大块模特轮廓。
- parser 对 HEAD/BODY 较好，对 HANDS 产生碎片。
- 分槽候选去模特在冻结高质量验证上使 Top-1 从约 29.6% 降至 16.7%。
- 全量验证零学习率对照约从 11.9% 降至 7.9%。

结论：当前 parser mask 引入的缺失和域差异大于去除模特信息的收益。
保留代码用于复现实验，但不要使用
`facebook-dinov2-base-equipment-selective-v2` 作为默认索引。

### 5.3 单纯扩大模型

synthetic canonical-render 训练曾在标准渲染 held-out 上达到约 79.5%
Top-1，但迁移到真实玩家图仍只有十几个百分点。这证明主要问题是域差异
和监督覆盖，不是 embedding 维度或网络层数不足。扩大模型可能增加容量，
但在当前数据条件下更可能放大过拟合。

### 5.4 只看高质量验证

高质量 validation 可达 30% 以上，而一次性 blind 只有 13.3%。后续不得
通过反复查看同一高质量 validation、挑每槽位最佳 checkpoint 来宣称泛化
改善。每轮关键架构变化都应收集新的 sealed glamour 组做一次性验证。

## 6. 推荐的下一阶段

### 6.1 先训练 v17 对应重排器

v17 hard-negative 查询编码器已优于 v16，但尚未训练配套重排器。建议从
以下命令开始：

```powershell
python scripts\train_glamour_pair_reranker.py `
  --index-dir data\indexes\facebook-dinov2-base-slot-aligned-v2 `
  --examples data\processed\glamour_examples.jsonl `
  --regions-dir data\debug\outfit-regions-v6-1882 `
  --split-manifest data\processed\glamour_split_v2.json `
  --query-checkpoint data\models\glamour_query_encoder_v17_534g_hardneg.pt `
  --query-cache data\processed\glamour_query_embeddings_v17_534g_hardneg_2169.npz `
  --checkpoint data\models\glamour_pair_reranker_v10_534g_hardneg.pt `
  --output data\processed\glamour_pair_reranker_eval_v10_534g_hardneg.json `
  --epochs 8 --patience 4 --batch-size 12 --learning-rate 3e-5 `
  --hard-image-k 96 --retrieval-image-k 400 `
  --candidate-k 200 --top-k 10 `
  --max-crops-per-example-slot 3 `
  --per-slot-heads --group-by-glamour --device cuda
```

只在 validation 选择 epoch。完成后用
`scripts/evaluate_visibility_filtered_report.py` 在冻结白名单上报告，但
不要重跑已消费 blind v5。

### 6.2 优先补 HANDS/FEET 真实视角

下一轮采集与伪标注应优先：

- 正面站立、手部不被武器/身体遮挡。
- 鞋完整入镜，主体占画面较大。
- 同一装备跨不同角色、染色和光照出现多次。
- 对每个槽位建立“可见/不可见”视觉标签，训练时排除不可见 crop。

VLM 可以审核“这个槽位是否清晰可见、是否正面全身”，但 exact item
标签必须来自页面结构化数据。

### 6.3 全覆盖原图前景缓存

如要继续 foreground 方向，应对 2,169 张图重建完整缓存，并记录：

- 原图人物 mask。
- mask 质量标志和视觉复核结论。
- 灰色合成与透明合成两种版本。
- 原图/foreground 成对训练，而不是只在评估时切换。

只有在相同 case 覆盖下同时超过 raw，才能将 foreground 升为默认。

### 6.4 新 blind 协议

1. 扩充新 glamour。
2. 更新 split，新组由稳定哈希产生 train/validation/blind。
3. 在看模型预测前完成全部 blind 图片质量审核。
4. 只评估通过的正面全身图。
5. 保存报告并将 blind 转为 confirmation。
6. 报告封存后才允许把 confirmation 转入下一轮 train。
