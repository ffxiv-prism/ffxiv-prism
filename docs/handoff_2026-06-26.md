# FFXIV Prism Handoff — 2026-06-26

This handoff captures the current repository state, active assumptions, recent
experiments, and recommended next steps so work can continue from another

## Current project goal

Build a local FFXIV glamour appearance matcher that can take a player-uploaded
outfit screenshot, crop likely equipment regions, and retrieve matching or
same-appearance equipment pieces from the local Eorzea Collection dataset.

The final product should allow same-appearance but non-identical item IDs, and
must label those results as same appearance rather than exact ID matches.

## Current dataset state

- Labeled player glamour examples: 50 glamour pages, 201 screenshots.
- Core evaluated slots: `HEAD`, `BODY`, `HANDS`, `LEGS`, `FEET`.
- Source file: `data/processed/glamour_examples.jsonl`.

## Implemented since the previous stable state

### Pose-driven screenshot cropper

New module:

- `src/ffxiv_prism/vision/outfit_regions.py`

Key behavior:

- Uses ViTPose (`usyd-community/vitpose-base-simple`) for single-person pose.
- Defaults all player screenshots to single-person images.
- Uses a full-image pose pass, then center-biased window search only when the
  initial pose is weak.
- Builds multiple pose-relative crops per slot rather than one hard crop.
- Adds `role` and `tags` metadata so retrieval can distinguish primary evidence,
  auxiliary overlap evidence, and context evidence.

Slot crop strategy:

- `HEAD`: full head, upper-accessory focus, face-accessory focus, context.
- `BODY`: torso, upper-arm overlap, context.
- `HANDS`: left/right arm, forearm crops, arm-cover context.
- `LEGS`: left/right leg, thigh focus, boot-overlap, context.
- `FEET`: left/right foot, boot-height crops, lower-leg context.

This explicitly models common FFXIV ambiguities:

- long sleeves vs long gloves;
- long boots covering leg equipment;
- head gear mixed with hair, face, eyewear, or masks;
- multi-slot equipment covering adjacent slots.

Debug CLI:

- `scripts/debug_outfit_regions.py`

Example:

```powershell

  --dataset data\processed\glamour_examples.jsonl `
  --output-dir data\debug\outfit-regions\overlap-final-201 --quiet
```

### End-to-end glamour matching evaluation

New script:

- `scripts/evaluate_glamour_matching.py`

It evaluates:

- exact ID metrics;
- same-appearance metrics via normalized appearance keys;
- per-slot Recall@K and MRR;
- crop weighting profiles (`primary`, `context`, `balanced`, `overlap`);
- tag penalty profiles;
- max vs sum crop aggregation.

Important baseline results on 943 eligible slot cases:

| Method | Exact/appearance Top1 | Recall@10 | MRR |
|---|---:|---:|---:|
| CLIP ViT-B/32 baseline | 2.44% | 7.95% | 0.038 |
| DINOv2-small | 4.24% | 13.36% | 0.065 |
| CLIP + DINOv2-small fusion | 4.98% | 14.85% | 0.076 |
| FashionCLIP color | 3.1% | 9.7% | 0.047 |

Best fusion profile from the local experiment:

- CLIP weight: 0.5
- DINOv2-small weight: 0.5
- crop weighting: `overlap`
- tag penalties: `mild`
- aggregation: `max`

Best fusion per-slot appearance metrics:

| Slot | Top1 | Recall@10 |
|---|---:|---:|
| HEAD | 3.6% | 15.5% |
| BODY | 11.6% | 30.2% |
| HANDS | 2.0% | 5.1% |
| LEGS | 4.8% | 15.1% |

Top-k ceiling check for the best fusion method:

| K | Recall@K |

Interpretation: correct pieces often do not enter the candidate pool early
enough. Reranking alone is not sufficient; the retrieval representation/domain
gap must improve.

### Reusable embedding-model evaluator

New script:

- `scripts/evaluate_glamour_embedding_model.py`

Purpose:

- Evaluate a single embedding model under a consistent end-to-end glamour
  matching protocol.
- Supports CLIP-like models, DINOv2, and preprocessing modes:
  `color`, `gray`, `edge`.
- Builds and caches candidate and crop embeddings under ignored local paths.

Example:

```powershell
python scripts\evaluate_glamour_embedding_model.py `
  --model-id patrickjohncyh/fashion-clip `
  --preprocess color `
  --candidate-k 200 `
  --top-k 10 `
  --batch-size 16 `
  --device cpu `
  --sweep
```

## Current working conclusions

1. The original static single-piece CLIP index is not broken:
   - transformed static single-item eval Recall@10: 100%;
   - cross-view static eval Recall@10: 80%.
2. The major problem is the cross-domain query:
   player screenshot crop -> clean static single-piece render.
3. Same-appearance ID normalization is necessary for product output, but it is
   not the main cause of current misses.
4. Crop weighting improves interpretability but does not solve retrieval
   quality by itself.
5. DINOv2-style local visual features help more than generic CLIP for this task.
6. FashionCLIP color did not beat CLIP+DINO fusion in the current full run.

## Immediate next plan

Continue the optimization sequence:

1. Finish color-suppressed experiments:
   - FashionCLIP gray;
   - DINOv2 gray;
   - CLIP gray;
   - optionally edge/high-pass preprocessing.
2. Install missing dependencies if useful:
   - `sentencepiece` for SigLIP processor;
   - possibly `torchvision`, `timm`, `open_clip_torch`.
3. Evaluate SigLIP or OpenCLIP variants if feasible on CPU.
4. Try foreground/background cleanup:
   - simple alpha/background suppression;
   - rembg/SAM-style foreground masking only if installation/runtime is viable.
5. If retrieval remains low, move to domain adaptation:
   - use player crop as query;
   - use labeled static equipment image as positive;
   - train a lightweight projection/reranker per slot or shared with slot
     conditioning.

Recommended success target before productization:

- Recall@10 should be substantially above 50% for BODY/HEAD and improving for
  HANDS/FEET before investing heavily in UI.
