# FFXIV Prism 当前状态与后续准入（2026-07-30）

## 一句话结论

项目已经形成可运行的五部位本地候选检索 Demo，但尚未达到“所有部位 Top-10 命中率 80%”的目标。BODY 已越过 Top-10 80%，HANDS 只有 8.78%，是当前差距最大的部位。下一轮不直接训练：必须先证明玩家搭配数据质量、数量、标签闭包、装备库覆盖和严格划分全部合格。

本文合并此前 v40–v99 阶段文档、报告和本地装备库更新结论。逐实验明细不再作为仓库长期资产；需要追溯时使用 Git 历史。

## 已推广方案

### BODY

- DINOv2 qv64 查询适配器提供稳定召回池。
- 零样本 DINOv3 与 e10 适配 DINOv3 提供互补排序。
- 冻结、标签无关的 Top-1 一致性门控只移动满足强一致条件的第一名，并保留完整 DINOv2 Top-1000 尾部。
- v99 三折 Top-1 为 627/987，Top-10 为 818/987；性别与九个种族切片无注册指标退化。

### HEAD

- DINOv2、SigLIP2、e3 适配 DINOv3 三分支融合。
- 查询使用上头部小饰品区域，候选路由到面部/头饰渲染，减轻裁剪口径错位。
- 形态分类器只输出低可信诊断，不改排序。
- 完整头饰包络用于宽帽檐、高帽冠和源图截断诊断，检索权重为 0。

### HANDS

- DINOv2 qv71、左右手/前臂/双臂上下文多裁剪、性别路由和 RRF(k=1)。
- 多槽占用 Top-1 门控只在明确的 BODY 支持关系下保留占位主件，否则允许邻近独立手部件上移。
- 当前方案仍然非常弱；3.07%/8.78% 只说明工程链路完整，不代表识别可用。

### LEGS

- DINOv2 与 DINOv3 在冻结 DINOv2 Top-1000 piece 池中融合。
- DINOv3 显著改善前排，三折 Top-1/Top-10 从早期 10.58%/26.39% 提升到 13.93%/31.94%。
- 旧灰度纵向空间重排能修复个别袜长/裙长错误，但与 DINOv3 叠加后退化，因此未串联。

### FEET

- 使用 `primary-family-v1` 清理候选，避免同一套装中与鞋无关的 piece 污染真值。
- DINOv2 + SigLIP2、查询多裁剪 RRF，当前 19.34%/41.16%。
- DINOv3 总体有互补收益，但冻结门控使 Hrothgar 切片退化，未推广。
- 完整鞋部包络覆盖鞋尖、厚底与脚踝以下区域；诊断大框不改身份排序。

## 已排除的方向与得到的根因线索

### HANDS：不是继续扫全局向量权重就能解决

以下方向均未跨过冻结验证门槛：

- DINOv3 零样本与 e3/e10 查询适配；
- 标准人台模板差分；
- 玩家图全局人物前景抑制；
- SAM2 手部前景；
- DINOv2/DINOv3 patch 全局汇总；
- 名称形态分类、简单像素质量拒识；
- 4,000 张合成手部域适配。

合成域内部可达 Top-1 78.2% / Top-10 98.7%，真实严格折却显著退化，说明核心不是模型容量不足，而是合成姿态/纹理与玩家截图的域差、手部有效像素过少、左右臂局部对应关系不稳定，以及手套与袖子/武器/身体主件互相遮挡。后续应优先验证姿态归一化的局部对应、多帧/多视图聚合、显式可见性标签和玩家域局部表征，不再把全局 CLS 融合当主要路径。

### HEAD：小件被头发、耳朵和脸主导

小型额饰、角、发带常只占几十像素，通用 embedding 容易把绿色头发、角色耳朵或脸当成主要特征。覆盖率、解析布局和形态硬路由在单例上看似合理，但跨折退化。根因更接近“目标像素少 + 奇幻人体部件混淆 + 候选渲染域错位”，需要小件定位/存在性监督，而不是再加一个全局类别阈值。

### LEGS / FEET：候选前排与外形拓扑同时受限

DINOv3 对长短、轮廓有互补性，但袜长、裙摆边界、鞋帮高度和厚底仍容易被颜色与身体上下文覆盖。局部空间特征可解释个别错误，却不能假定跨部位通用。应把“候选未召回”和“已召回但排序错误”分开统计。

### BODY：Top-10 已达标，细粒度 Top-1 仍不足

BODY 的主要问题已从候选覆盖转为相似外观细排。继续增加深层候选不如建立外形属性、染色不变性和局部细节成对偏好监督。

## 玩家搭配数据现状

当前闭包标签集包含 1,617 个 glamour、6,447 张本地图片。原始解析中共有 7,624 个 exact item 标签、125 个 appearance-equivalent 标签和 191 个未匹配标签；官方同模闭包又为 402 个槽位标签补充了 833 个 piece ID。

最终 v46 质量清单只接受 1,105/6,447 张（17.14%）。自动姿态门槛曾接受 2,099 张，但最终清单叠加人工视觉复核后更严格。这个数量不能仅凭“约一千张”就认定充足，尤其不能认为每个部位、外观形态、种族、性别、遮挡和可见性都已覆盖。

## 下一轮训练的硬准入

训练入口必须消费规范标签和质量清单，不得绕开。准入报告至少包含：

1. 图片完整性：文件存在、可解码、尺寸与清单一致；
2. 质量一致性：训练/验证记录全部 `passed=true`，人工否决优先；
3. 标签完整性：每槽标签非空、piece ID 合法、同模闭包可解释；
4. 装备库覆盖：真值在 SQLite、主候选索引和所有用于融合的必要分支中存在；
5. 去重与泄漏：同 glamour、同图片内容、近重复图、同官方外观族不得跨 train/validation；
6. 数量与多样性：逐槽报告图片数、glamour 数、外观族数、单例率、每族视图数、性别/种族/姿态/遮挡切片；
7. 可见性：目标部位实际可见，而不是仅因全身姿态合格就自动纳入；
8. 统计把握：验证集分母足以判断 80% 目标，并给出置信区间；
9. 失败漏斗：区分库中不存在、Top-1000 未召回、Top-10 未进入和 Top-10 内排序错误。

任何槽位未通过时，训练保持阻塞，优先补采/复核/修库。

## 后续优先级

1. 完成训练准入审计并冻结报告；
2. 对 HANDS 做人工可见性小样本复核和失败漏斗，确认低分主要来自标签不可见、裁剪失败、候选渲染姿态差还是表征失败；
3. 若 HANDS 数据不足，先按失败类型定向扩充玩家图与多视图，不训练；
4. 若数据通过，验证姿态归一化局部匹配或多视图玩家 exemplars；
5. 每个方案先在开发折选参，再冻结到另两折；不得反向用验证折调阈值；
6. HEAD、FEET、LEGS 按 Top-10 缺口依次推进；BODY 只做不破坏 82.88% Top-10 的保守改进。
