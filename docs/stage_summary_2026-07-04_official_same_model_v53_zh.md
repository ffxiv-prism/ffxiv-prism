# 官方同模真值改造与 v53 阶段总结（2026-07-04）

## 一、结论

本阶段完成了两件关键工作：

1. 用公开游戏模型字段和灰机 Wiki 的同模规则，替换原先基于图像相似度的同模推断；
2. 在官方同模族完全不相交的三折协议中重新训练查询编码器和重排器。

当前结果分为两个口径：

| 场景 | 当前方案 | Top-1 | Top-10 | 解释 |
|---|---|---:|---:|---|
| 混合/可能见过同外观的部署参考 | qv52 + v35 + v2 索引 | 60/81，74.1% | 72/81，88.9% | 固定公开验证集，官方同主模型计分 |
| 独立 confirmation 参考 | 同一部署模型 | 9/10，90.0% | 10/10，100% | 样本太小，只能作为过拟合警报 |
| 严格未知外观 | v52 查询编码器 + v53 重排器 + v3 索引 | 453/987，45.90% | 735/987，74.47% | 训练与验证的官方同模族交集为零 |

公开验证上的旧路由 v9 在新真值下达到 66/81（81.5%）Top-1，但路由尺度曾在同一验证集上选择；它在独立 confirmation 集没有优于单模型，因此不晋级为可信默认方案。

严格 v53 相比旧的 v44 严格基线 40.3%，提高 5.6 个百分点，或相对提高约 13.9%。这满足“最优结果相对提高 10%”的阶段条件，但未知外观 Top-1 仍远未达到 80%。

当前成熟评测范围仍只有 `BODY`，不能外推为五槽位总体准确率。

## 二、官方同模真值

### 1. 数据源结论

- XIVAPI v2 可以提供游戏表字段，但不直接提供页面式“同模型装备”关系。其迁移文档明确说明 v2 不支持多数计算字段，也没有 v1 的反向 `GameContentLinks`。
- FFXIV Armoury Collection 和 ConsoleGamesWiki 页面存在 `Shared Models`，可用于抽样交叉验证。
- 灰机 Wiki 的 `模块:Item/Page` 公开了同模分组规则，并区分：
  - `模型完全相同物品`；
  - `主模型相同物品`。

### 2. 灰机规则的本地复现

当前样本库只包含可见护甲槽位。对这些物品：

- 同 `ItemUICategory` 且 `ModelMain[0]` 相同：主模型相同；
- 在此基础上 `ModelMain[1]` 也相同：模型完全相同。

`ModelMain` 是游戏客户端物品表里的模型编号，不是视觉模型估算值。

最新版 `Item.csv` 来自 `xivapi/ffxiv-datamining` 的客户端数据提取：

- 游戏物品表：52,801 行；
- 本地装备部件：11,737 个；
- 成功映射：11,737/11,737，100%；
- 主模型同模组：2,740 个；
- 完全同模组：716 个；
- 宽松同模边：18,962 条；
- 完全同模边：4,690 条。

瓦纳·迪尔治愈手套的模型字段为 `[961, 1, 0, 0]`，瓦纳·迪尔咏咒手套为 `[961, 2, 0, 0]`：两者主模型相同，但不是完全同模。这与灰机页面的两级定义一致。

### 3. 旧推断的问题

旧 DINOv2 图像阈值关系有 31,344 条边，其中只有 7,160 条被官方宽松同模关系支持：

- 旧推断相对官方宽松关系的边精度约 22.8%；
- 旧推断漏掉 11,802 条官方宽松关系；
- 因此旧同模图既有大量误连，也有明显漏连。

评测已禁用名称归一化命中兜底；成功必须是标签中的明确 `piece_id` 或其官方同模 ID。

### 4. 标签闭包修复

旧富化器对 `Augmented`、`Replica` 等名称兜底匹配没有继续应用同模闭包，导致同一外观族可能得到不同分组键。本阶段统一处理全部标签：

- 修正标签：402 个；
- 补入官方同模 piece ID：833 个；
- 新三折每折 330 张高质量验证图；
- 每折训练/验证官方同模 piece ID 交集：0。

## 三、当前最佳严格算法：v52 查询 + v53 重排 + v3 索引

```text
高质量玩家搭配图
  → 人体姿态与 BODY 多区域裁剪
  → v52 查询编码器生成 768 维视觉向量
  → v3 多尺度标准装备索引召回 1000 个候选
  → v53 非线性成对重排器重新排序
  → 多裁剪固定 max 融合
  → 按精确物品或官方同主模型关系计分
```

### 1. ViTPose

ViTPose 是人体姿态估计模型，通过肩、肘、腰、膝等关键点定位人物。项目用它生成躯干、手臂重叠和上下文裁剪，并辅助剔除背面、侧面或严重遮挡图片。

### 2. DINOv2

DINOv2 是自监督视觉 Transformer，不需要文本标签也能学习形状、纹理和部件结构。这里以 `facebook/dinov2-base` 为骨干，将玩家截图和标准装备渲染图映射到同一 768 维空间。

### 3. 查询编码器 v52

- 每折从基础 DINOv2 独立初始化；
- 微调最后一个 Transformer block；
- 使用槽位注意力池化；
- 固定训练 10 epoch；
- 学习率 `5e-7`；
- 按 glamour 聚合多个裁剪；
- 使用 v46 的完整高质量清单和官方同模正样本。

对比学习让同一装备/官方同模装备向量靠近，让错误候选远离。它负责从大索引中建立高召回候选池。

### 4. v3 多尺度候选索引

每件 BODY 装备同时保留 `upper_body` 和更紧的 `torso_core` 标准渲染裁剪。相对 v2 单尺度索引，v3 将同一 v52 模型的最终 Top-1 从约 39.4% 提升到 44.5%。

### 5. v53 非线性重排器

重排器是一个小型 MLP，输入包括：

- 查询与候选向量的逐维乘积；
- 逐维绝对差；
- 余弦相似度；
- 槽位嵌入。

v53 直接在 v3 多尺度候选分布上训练，固定 7 epoch，每个样本使用最多 1000 个困难候选。它相比在 v2 上训练、到 v3 上评测的 v52 重排器：

- Top-1：439 → 453，增加 14；
- Top-10：730 → 735，增加 5；
- 女性 Top-1：277 → 284；
- 男性 Top-1：162 → 169。

## 四、严格漏斗结果

987 个可评估高质量 BODY 案例：

| 阶段 | Top-1 | Top-10 | Top-100 | Top-1000 |
|---|---:|---:|---:|---:|
| 基础 DINOv2 | 253，25.63% | 477，48.33% | 737，74.67% | 952，96.45% |
| v52 查询编码器 | 364，36.88% | 669，67.78% | 913，92.50% | 987，100% |
| v53 重排器 | 453，45.90% | 735，74.47% | 约 94.6% | 100% |

分折 Top-1：

- Fold 1：143/328，43.6%；
- Fold 2：163/329，49.5%；
- Fold 3：147/330，44.5%。

分性别 Top-1：

- Female：284/640，44.38%；
- Male：169/347，48.70%。

当前候选池覆盖已不是主要问题：查询 Top-1000 达到 100%，Top-100 也超过 92%。下一阶段的主要瓶颈是把已召回的相似候选可靠地压到 Top-1，以及继续提升 Top-10 内的细粒度排序。

## 五、阶段决策

- 晋级 v53 为严格未知外观研究基线；
- 保留 qv52 + v35 + v2 为部署默认模型；
- v9 路由不晋级，81.5% 只记录为有选择偏倚的公开验证结果；
- 不查看 blind pool；
- 后续优先研究候选间细粒度局部结构、袖型/领口/甲片区域特征和更强的成对/列表式排序目标，而不是继续扩大候选 K。
